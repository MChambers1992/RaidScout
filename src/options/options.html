Proactive Score Filter (all sites)

Set your parse thresholds once here. They drive proactive WCL filtering on WoWProgress, Raider.IO and Guilds of WoW — switch it on per-site in each section. The DPS values also auto-close a WarcraftLogs character tab opened from those sites when the parse is below threshold.

Min. Best % Min. Median % DPS Tank Healer

Ranks candidates by parse (highest first) on every site with proactive filtering on, instead of only hiding those below your thresholds. Previously this was three separate per-site toggles; your existing choice carries over.

Best is the highest single parse on any fight; Median is the middle parse across all of them. DPS and Tank are measured on damage, Healers on healing (HPS) — RaidScout picks the right metric per character automatically. Leave Tank blank to reuse the DPS row.

Characters WarcraftLogs has no parse data for are treated as below every threshold and hidden — an unparsed raider can't be judged against a parse minimum. Characters whose lookup failed (no credentials, rate limit, timeout) are always left visible, so a misconfiguration can never empty a page.

Scout

Scout gathers candidates from every site below in one pass and merges them into a single de-duplicated list, so you don't have to open four tabs and read four layouts. Each site is filtered by its own settings from the tabs above, then every unique player is scored once against your WarcraftLogs thresholds. Open it from the extension popup.

Sources

WoWProgress is read directly over the network. The other three render their listings in the browser, so Scout opens each one in a background tab for a few seconds, reads the filtered results and closes it again — you never have to look at them.

Limits

Every candidate past the de-duplication step costs one WarcraftLogs API lookup. The WCL API allows roughly 3,600 points per hour, so a cap around 150 keeps a run comfortably inside it. Scores are cached for 6 hours, which makes a repeat run of the same candidates nearly free.

How many pages of the WoWProgress listing to pull. Only applies to WoWProgress — the background-tab sources always harvest whatever their first page renders.

Scoring

Uses the same API credentials, role-aware metrics and cache as proactive filtering. With no credentials saved, Scout still lists everyone — it just can't rank them by parse.

Applies the parse thresholds from the WarcraftLogs tab. Candidates WarcraftLogs has no logs for are hidden too — a Scout run is meant to be a finished shortlist, and an unparsed raider can't be judged against a parse threshold. Candidates that couldn't be scored (no credentials, scoring off, rate limit, lookup error) are always shown, so a misconfiguration can never empty the list. You can also toggle this directly on the Scout page.

Listing URLs — point a source at a different search

Leave blank to use the defaults. Set these to the exact listing you normally browse — a specific realm, region or role filter — and Scout will harvest that instead. These also let you repoint Scout yourself if a site moves its recruitment page.
